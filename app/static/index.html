Prompt optimisation (GEPA)

      

        Runs the genetic-Pareto optimisation on the server for the
        currently selected dataset: the judges score a batch of
        questions, the reflection model proposes child prompts, and the Pareto
        rule keeps only non-regressing improvements. Expect
        hundreds of model calls and 15–40 minutes on the
        light budget. When it finishes, the optimised prompt becomes available
        in step 2. On Railway the file persists only until the next deploy —
        commit prompts/<dataset>/optimized.txt to keep it.
